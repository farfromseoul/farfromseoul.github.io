2026년 11월 26일(미국 시각), OpenAI가 GPT-6.2 Astra·Sol 모델의 사용량 계산 오류를 고쳤다고 밝혔습니다. 11월 17일 출시 때부터 두 모델의 사용량이 실제보다 적게 잡혀, 구독자가 원래 의도보다 더 많이 쓸 수 있었다는 것입니다. 이틀 앞선 11월 24일에는 ChatGPT의 Chat 탭과 Work 탭을 합치고 사용량 한도도 하나로 묶는 작업을 일부 Pro 사용자부터 시작했습니다. 핵심만 먼저 보면 이렇습니다.

  • 같은 작업을 해도 지난주보다 Astra는 약 40%, Sol은 약 25% 빨리 요금제 한도에 닿습니다. 요금(가격)이 오른 것은 아닙니다.
  • 이미 쓴 만큼에 대해 추가 청구는 없고, 다른 모델은 영향이 없습니다.
  • 대신 Go·Plus·Pro·Business 사용자에게 한 번 쓸 수 있는 사용량 리셋을 줍니다.
  • 12월부터 Plus·Pro·Business에서 Chat·Work(와 Codex)가 한 개의 사용량 한도를 나눠 쓰는 방식으로 바뀐다고 보도됐습니다. Instant 모델 대화는 이 한도에 포함되지 않습니다.

이 글은 OpenAI 공식 도움말과 담당자 X 게시물을 이 환경에서 직접 열 수 없어, TechCrunch·The Next Web·Decrypt·Notebookcheck·tbreak 보도 중 두 곳 이상이 같은 내용을 쓴 것만 담았습니다(2026-11-28 확인 기준). 매체마다 엇갈린 부분은 따로 표시했습니다.

먼저 용어 몇 가지

  • 사용량 한도(usage limit): 정해진 시간(예: 5시간, 1주) 동안 쓸 수 있는 양입니다. 다 쓰면 다음 주기까지 해당 모델을 못 쓰거나 제한됩니다.
  • GPT-6.2 Astra·Sol: 11월 17일 Work 탭과 Codex 데스크톱 앱에 미리보기로 나온 GPT-6.2 계열 모델 두 가지입니다. 11월 23일부터는 Chat 탭에도 GPT-6.2가 들어갔습니다.
  • Chat 탭·Work 탭: Chat은 일반 대화, Work는 문서 작업·에이전트 작업처럼 오래 걸리는 일을 맡기는 화면입니다.
  • Instant 모델: 깊게 추론하지 않고 바로 답하는 가벼운 모델입니다.
  • Codex: OpenAI의 코딩 에이전트 제품입니다. ChatGPT 요금제로 함께 씁니다.

무엇이 달라졌나

1) 과금 오류 수정: “더 비싸진 것"이 아니라 “원래대로 계산”

항목내용
대상 모델GPT-6.2 Astra, GPT-6.2 Sol (다른 모델 영향 없음)
변화같은 작업이 요금제 한도를 더 많이 씀
체감 폭(지난주 대비)Astra 약 40%, Sol 약 25% 빨리 한도 도달
지난 사용분추가 청구 없음
가격표바뀌지 않음

여기서 40%·25%는 한도가 닳는 속도를 말합니다. 구독료나 API 단가가 오른 것이 아닙니다. 일부 매체 제목의 “최대 40%“는 Astra 기준 수치이고, Sol은 25%입니다.

2) 1회 리셋

항목내용
받는 요금제Go, Plus, Pro, Business
효과남은 한도를 한 번 가득 채움 (Plus는 5시간·주간 한도, Go는 월간 한도)
쓰는 곳설정의 사용량(Usage) 메뉴 — 웹·데스크톱 앱
한계한 번뿐이며, 한도를 영구히 늘리거나 지난주 계산 방식으로 되돌리지 않음

무료(Free) 요금제는 Astra·Sol을 쓸 수 없어 대상이 아니고, Enterprise는 리셋 대상 목록에 이름이 없습니다. 리셋을 쓸 수 있는 세부 조건(남은 양 기준, 만료일)은 리셋 화면에 표시된다고 보도됐으니, 누르기 전에 화면 안내를 확인하세요.

3) Chat·Work 통합과 공유 한도

항목내용확인
지금일부 Pro 사용자에게 통합 화면·공유 한도 먼저 적용TechCrunch·Decrypt
12월부터Plus·Pro·Business가 한 한도를 Chat·Work·Codex에서 나눠 씀Decrypt·Notebookcheck·tbreak
제외Instant 모델 대화는 한도에 안 들어가고, 한도를 다 써도 계속 사용 가능TechCrunch(OpenAI 대변인) 외
OpenAI 설명대부분은 한도에 더 자주 걸리지 않고, 가장 많이 쓰는 일부만 더 빨리 걸릴 수 있음TechCrunch
공개 안 된 것합쳐진 한도의 전체 크기, 지금보다 줄어드는지 여부Decrypt

매체마다 엇갈리는 부분

  • 공유 한도 대상: TechCrunch는 “일부 Pro 먼저, 12월에 더 넓게"라고만 쓰고 요금제를 나열하지 않았습니다. 다른 세 매체는 Plus·Pro·Business를 명시했습니다.
  • Chat 탭 메시지 한도: 이번 과금 수정이 Chat 탭 GPT-6.2 사용에도 그대로 적용되는지는 Notebookcheck·tbreak 모두 “확인되지 않았다"고 썼습니다.
  • Decrypt가 든 “남은 한도 50%가 70%처럼 줄어든다” 식의 예시는 매체가 직접 계산한 예시라 이 글에서는 쓰지 않았습니다.

성능 수치는 이번 소식과 관계없습니다

이번 변화는 모델 성능이 아니라 사용량 계산에 관한 것입니다. GPT-6.2 자체의 성능은 GPT-6.2 Astra·Sol 리뷰 글에서 다뤘습니다. 이번 발표에 새로 나온 벤치마크 수치는 없습니다.

한계·주의할 점

  • “40%“는 평균적인 체감 폭입니다. 실제로 얼마나 빨리 닳는지는 작업 길이, 추론 설정, 도구 사용에 따라 달라집니다.
  • 전체 한도 크기는 공개되지 않았습니다. 그래서 “12월부터 덜 쓰게 된다"고도, “괜찮다"고도 아직 단정할 수 없습니다.
  • 출시 직후 넉넉했던 사용량은 오류 덕분이었습니다. 지난주 사용 경험으로 이번 달 작업량을 잡았다면 다시 계산해야 합니다.
  • 리셋은 한 번뿐입니다. 한도가 조금 남았을 때 쓰면 아깝고, 마감 직전 긴 작업이 몰릴 때 쓰는 편이 낫습니다.

나에게 맞는 선택

  • 입문자·학생(Go·Plus로 가끔 사용): 대부분은 체감이 크지 않을 가능성이 큽니다. 간단한 질문은 Instant 모델로 하면 한도에 들어가지 않습니다. 리셋은 시험·과제 마감처럼 몰아 쓰는 때를 위해 아껴 두세요.
  • 개발자(Work·Codex로 긴 작업): 가장 크게 영향을 받는 쪽입니다. Astra가 Sol보다 더 빨리 닳으니, 꼭 Astra가 필요한 작업이 아니면 Sol이나 가벼운 모델로 나눠 쓰는 것을 고려하세요. 12월 공유 한도가 오면 Chat에서 쓴 양도 Codex 몫을 줄이므로, 주간 사용량 화면을 한 번씩 확인하는 습관이 도움이 됩니다.
  • 팀 관리자(Business): 팀원들이 “갑자기 한도가 빨리 찬다"고 할 수 있습니다. 오류 수정과 12월 변경을 미리 공지해 두면 문의가 줄어듭니다.

정리

OpenAI가 GPT-6.2 Astra·Sol의 사용량을 적게 계산하던 오류를 고치면서, 같은 일을 해도 한도가 Astra는 약 40%, Sol은 약 25% 빨리 찹니다. 가격은 그대로이고 지난 사용분 청구도 없으며, 유료 요금제에는 1회 리셋이 주어집니다. 12월부터는 Chat·Work·Codex가 하나의 한도를 나눠 쓰는 방식으로 바뀔 예정인데, 전체 한도 크기는 아직 공개되지 않았습니다. 많이 쓰는 사람일수록 이번 주부터 사용량 화면을 확인해 보세요.
