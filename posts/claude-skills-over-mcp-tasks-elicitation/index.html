  • Skills over MCP(공개 베타): MCP 서버가 도구뿐 아니라 “이 도구들을 어떤 순서로 어떻게 쓰라"는 스킬(작업 지침) 까지 함께 보냅니다. 사용자가 따로 설치할 것이 없고, 서버가 바뀌면 스킬도 같이 바뀝니다.
  • Tasks(정식 출시): 오래 걸리는 작업을 서버가 뒤에서 돌리고, Claude는 그동안 다른 일을 하다가 결과가 나오면 이어 받습니다.
  • Elicitation(정식 출시): 서버가 작업 도중 멈추고 사용자에게 확인이나 입력을 요청합니다. 결제·삭제처럼 되돌리기 어려운 작업 앞에서 쓰입니다.
  • File Uploads(“곧 제공”): PDF·표·이미지를 대화 맥락을 거치지 않고 MCP 서버로 바로 넘깁니다.
  • 대상은 Claude 앱과 Claude Code이며, Pro·Max·Ultra가 먼저이고 Team·Enterprise는 단계적으로 열립니다.
  • 성능 벤치마크는 없고, 발표에 나온 숫자(SDK 내려받기 수, 맥락 절감률)는 모두 Anthropic이 밝힌 값이며 측정 방법은 공개되지 않았습니다(2026-11-26 확인 기준).

먼저 용어 몇 가지

  • MCP(Model Context Protocol): AI 앱이 외부 서비스(깃허브, 데이터베이스, 사내 시스템 등)의 기능을 같은 방식으로 불러 쓰게 해 주는 공개 표준입니다. 지금은 Agentic AI Foundation이라는 재단이 관리합니다.
  • MCP 서버 / 클라이언트: 기능을 내주는 쪽이 서버(예: Supabase가 만든 MCP 서버), 그 기능을 쓰는 AI 앱이 클라이언트(예: Claude, Claude Code)입니다.
  • 커넥터: Claude에서 MCP 서버를 연결해 쓰는 단위를 부르는 이름입니다.
  • 스킬(Skill): 특정 일을 해내는 절차와 요령을 적은 문서 묶음입니다. 필요할 때만 불러 읽기 때문에 평소에는 맥락을 거의 차지하지 않습니다.
  • 맥락(context window): 모델이 한 번에 읽고 기억하는 텍스트 분량입니다. 도구 설명이 많을수록 여기가 빨리 찹니다.

무슨 일이 있었나

그동안 MCP 서버는 주로 “도구 목록"만 내줬습니다. 도구를 어떻게 조합해야 원하는 결과가 나오는지는 사용자가 프롬프트로 설명하거나, 따로 스킬 파일을 만들어 설치해야 했습니다. 또 도구 호출은 끝날 때까지 기다려야 했고, 위험한 작업을 앞두고 사용자에게 다시 묻는 표준 방법도 클라이언트마다 달랐습니다.

이번 발표는 이 세 가지 불편을 MCP 표준과 그 확장(extension) 쪽에서 풀었다는 내용입니다. Anthropic은 이 기능들이 공개 사양에 들어 있어서 같은 기능을 지원하는 다른 클라이언트에서도 동작한다고 설명합니다. 다만 클라이언트마다 해당 확장을 지원해야 쓸 수 있다는 점은 독립 매체도 짚었습니다.

무엇이 달라졌나

  • Enterprise Managed Auth: 관리자가 지원되는 서버를 한 번 승인하면 직원들은 따로 로그인하지 않고 연결됩니다.
  • MCP Apps: 서버가 대화 옆이나 전체 화면에 자체 화면(UI)을 띄울 수 있습니다.

세 숫자 모두 Anthropic이 직접 밝힌 값이며, 어떤 환경을 기준으로 어떻게 쟀는지는 발표에 없습니다. 특히 85%는 “도구가 아주 많은 여러 서버 환경"이라는 조건이 붙은 최대치에 가깝게 읽어야 합니다. 서버 하나만 쓰는 경우에도 그만큼 줄어든다는 뜻은 아닙니다. AlphaSignal은 SDK 내려받기 수에 자동 빌드나 반복 설치가 섞일 수 있다고 지적했습니다. 이 기능들은 모델 성능이 아니라 연결 방식에 관한 것이라 LMArena 같은 독립 순위표의 평가 대상도 아닙니다.

한계·주의할 점

  • 신뢰 범위가 넓어집니다. 스킬은 Claude가 따라 하는 “지침"입니다. 서버가 스킬을 바꾸면 사용자가 아무것도 설치하지 않아도 Claude의 행동이 달라질 수 있습니다. 편리함의 반대편이 이것입니다. AlphaSignal도 이 점을 들어 서버를 만든 곳과 권한을 살피고 서버 업데이트를 시험해 보라고 권했습니다. 공식 발표문에는 보안 항목이 따로 없습니다.
  • “확인 창"은 최소한의 안전장치입니다. Elicitation으로 삭제 전에 한 번 묻는다고 해서, 서버 쪽 권한 검사·감사 로그·좁은 범위의 접속 권한이 필요 없어지는 것은 아닙니다. 확인 버튼을 습관처럼 누르게 되는 것도 경계해야 합니다.
  • 링크로 받는 입력은 주소를 확인하세요. Elicitation은 폼뿐 아니라 링크를 열어 입력받는 방식도 씁니다. 로그인·결제 화면이 열리면 주소가 정말 그 서비스인지 직접 확인하는 습관이 필요합니다.
  • Tasks는 “끝났는지"를 사람이 놓치기 쉽습니다. 뒤에서 돌아가는 작업이 실패하거나 다시 시도될 때, 비용이 드는 작업이 두 번 실행되지 않는지 서버 개발자가 챙겨야 합니다.
  • File Uploads는 아직 실험 단계입니다. 발표 페이지가 연결한 저장소 이름부터 “experimental"이고, 공개 시점도 “곧"입니다. 사양이 바뀔 수 있다고 보고 기다리는 편이 낫습니다.
  • 요금제·조직에 따라 시기가 다릅니다. 개인 유료 요금제가 먼저이고, Team은 관리자가 Skills를 켜야 하며, Enterprise의 Skills는 아직 “곧"입니다. 회사 계정에서 안 보인다면 이 때문일 가능성이 큽니다.
  • 출처가 회사 발표 중심입니다. 독립 매체 보도도 대부분 발표를 정리한 수준이고, 실제 사용 경험이나 보안 검증 자료는 아직 적습니다.

나에게 맞는 선택

  • 입문자·학생: Pro 이상이면 이미 쓰는 서비스(예: GitHub, Atlassian)의 커넥터를 Claude에 연결해 보는 정도로 충분합니다. 이번 변화로 “프롬프트를 길게 쓰지 않아도 서비스가 알아서 절차를 알려 주는” 경험이 늘어납니다. 대신 결제·삭제 확인 창이 뜨면 내용을 읽고 누르세요.
  • 개발자(MCP 서버를 만드는 쪽): 우리 서비스에 정해진 작업 순서가 있다면 스킬로 묶어 배포할 가치가 큽니다. 오래 걸리는 작업은 Tasks로, 위험한 작업은 Elicitation 확인을 넣되 서버 쪽 권한 검사는 그대로 두세요. 구현 방법은 MCP 공식 사이트의 확장 문서와 Claude Code 문서의 MCP 항목에 정리돼 있습니다.
  • 팀·회사 관리자: Team 요금제라면 Skills over MCP를 켜기 전에 어떤 커넥터를 허용할지 목록부터 정하는 것이 좋습니다. 스킬은 서버 쪽에서 바뀌므로, 허용한 서버가 믿을 만한 곳인지가 곧 보안 정책이 됩니다.

정리

이번 발표의 요점은 MCP 서버가 “도구 상자"에서 “도구 상자 + 사용 설명서 + 확인 절차"로 커졌다는 것입니다. Skills로 절차를, Tasks로 긴 작업을, Elicitation으로 사용자 확인을 표준 안에서 다룰 수 있게 됐습니다. 반대로 서버가 Claude의 행동에 미치는 영향도 커졌기 때문에, 어떤 서버를 연결할지 고르는 일이 전보다 더 중요해졌습니다. 발표된 수치는 모두 회사가 밝힌 값이라는 점도 함께 기억해 두세요.
