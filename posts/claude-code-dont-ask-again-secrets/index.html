"다시 묻지 않기" 한 번에 비밀번호가 깃허브로: Claude Code 승인 기록에서 나온 비밀값 2,539개

Claude Code에서 명령을 '다시 묻지 않기'로 승인하면 그 명령이 비밀번호째 설정 파일에 저장되고, 이 파일이 공개 깃허브 레포 수천 곳에 올라가 있었습니다. 어떻게 새어 나갔는지, 왜 비밀값 스캐너도 놓쳤는지, 지금 내 레포에서 확인할 것을 정리합니다.

2026년 11월 초, 보안 회사 Apiiro가 공개 깃허브 레포를 조사한 결과를 발표했습니다. AI 코딩 도구 Claude Code의 로컬 설정 파일 .claude/settings.local.json을 들여다보니, 데이터베이스 비밀번호·클라우드 키·SSH 로그인 정보가 평문으로 수천 개나 들어 있었다는 내용이에요.

해킹이나 버그가 아니라, 개발자가 매일 누르는 버튼 하나 — “Yes, and don’t ask again”(예, 다시 묻지 않기) — 와 깃 커밋 습관이 겹쳐서 생긴 일입니다. AI 에이전트를 쓰는 개발자라면 오늘 바로 확인해 볼 만한 내용이라 정리해 봅니다.

무슨 일이 있었나

여러 보도(Cyber Security News, GBHackers)가 공통으로 전한 Apiiro 조사 결과만 추리면 이렇습니다.

항목내용

Apiiro는 공개된 파일만 분석했고, 찾은 비밀값으로 실제 접속을 시도하지는 않았다고 밝혔습니다. 그래서 “비밀값"은 진짜 자격 증명으로 보이는 값이라는 뜻이지, 전부 유효하다는 확인은 아니에요.

먼저 용어 몇 가지

  • AI 코딩 에이전트: 터미널 명령을 직접 실행하고 파일을 고치는 AI 도구. Claude Code, Cursor, Codex CLI 같은 것들이에요.
  • 권한 승인(permission prompt): 에이전트가 명령을 실행하기 전에 “이거 실행해도 될까요?” 하고 묻는 창.
  • allow 규칙: “이 명령은 묻지 말고 실행해도 된다"는 허용 목록 한 줄.
  • 비밀값(secret): 비밀번호, API 키, 토큰처럼 남이 알면 안 되는 접속 정보.
  • 비밀값 스캐너: 코드 속에 비밀값이 섞여 있는지 찾아 주는 도구. Gitleaks와 TruffleHog가 대표적이고, 주로 “키는 이렇게 생겼다"는 패턴으로 찾습니다.
  • .gitignore / 전역 git excludes: 깃이 추적하지 않을 파일 목록. .gitignore는 레포 안에 커밋되어 팀 전체에 적용되고, 전역 excludes 파일은 내 컴퓨터에만 적용됩니다.

어떻게 새어 나갔나

흐름은 네 단계예요.

  1. 에이전트가 비밀번호가 들어간 명령을 만든다. “DB 상태 좀 봐 줘"라고 하면 에이전트가 설정 파일의 비밀번호를 읽어 PGPASSWORD=... psql ... 같은 명령을 조립합니다.
  2. 개발자가 “다시 묻지 않기"를 누른다. 공식 문서에 따르면 이 선택은 승인한 명령을 .claude/settings.local.json에 allow 규칙으로 저장해요. 명령 문자열이 그대로 저장되니 비밀번호도 함께 저장됩니다.
  3. 파일이 커밋된다. 이 파일은 원래 커밋되지 않게 되어 있는데, 그 보호막에 구멍이 있었습니다(아래에서 설명).
  4. 레포가 공개된다. 공개 레포, 그리고 그 레포를 복제한 포크까지 비밀번호가 따라갑니다.

“원래 커밋 안 되는 파일” 아니었나?

공식 문서에 따르면 Claude Code는 깃 레포 안에서 이 파일을 처음 쓸 때, 전역 git excludes 파일에 **/.claude/settings.local.json을 추가합니다. 대부분은 이걸로 막혀요. 하지만 보도에서 짚은 빈틈은 이렇습니다.

상황왜 막히지 않나
다른 컴퓨터·다른 클론에서 작업전역 excludes는 내 컴퓨터 설정이라 레포를 따라가지 않음
이미 깃이 추적 중인 파일ignore 목록은 이미 추적 중인 파일에는 효과가 없음
파일을 손으로 만든 경우문서도 이 경우는 직접 .gitignore에 넣으라고 안내
나중에 git init한 폴더파일을 쓸 당시 레포가 아니었으면 제외 규칙이 안 들어갔을 수 있음

여기에 git add -A나 git add .로 폴더째 커밋하는 습관이 겹치면, 파일은 아무 경고 없이 올라갑니다.

왜 스캐너도 놓쳤나

AWS 키나 GitHub 토큰은 AKIA..., ghp_...처럼 생김새가 정해져 있어서 스캐너가 잘 찾습니다. 그런데 이번에 나온 비밀값의 상당수는 사람이 정한 평범한 비밀번호였어요.

  • PGPASSWORD= 뒤에 붙은 DB 비밀번호
  • sshpass -p 뒤의 SSH 비밀번호
  • mysql -p 뒤의 MySQL 비밀번호
  • 요청 헤더에 넣은 토큰

이런 값은 정해진 접두사가 없어서 패턴 기반 스캐너가 알아보기 어렵습니다. 1,122개 파일 중 215개를 두 스캐너가 모두 놓친 이유예요. “스캐너를 돌렸으니 괜찮다"가 통하지 않는 영역이 있다는 뜻입니다.

한계와 주의할 점

  • 수치는 Apiiro 한 곳의 조사입니다. 여러 매체가 보도했지만 모두 같은 조사를 인용한 것이고, 독립적인 재현은 아직 없어요. 2,539개와 1,379개처럼 집계 범위가 다른 숫자가 섞여 있으니 인용할 때 범위를 같이 적어야 합니다.
  • Anthropic의 공식 입장은 보도에 나오지 않았습니다. 11월 8일 기준, 저장 방식을 바꾸겠다는 발표는 확인되지 않았어요.
  • Claude Code만의 문제는 아닙니다. 승인한 명령을 기억하는 기능은 다른 에이전트 도구에도 흔합니다. “승인 기록이 어디에, 어떤 형태로 저장되나"는 어떤 도구든 확인해야 할 질문이에요.
  • 로컬에 있는 것만으로도 위험할 수 있습니다. 보도는 평문 설정 파일이 감염된 PC에서 악성코드에 그대로 읽힐 수 있다는 점도 짚었습니다. 커밋 여부와 별개로, 명령 속 비밀번호 자체가 문제의 뿌리예요.

독자가 해 볼 것

1. 내 레포에 이 파일이 올라가 있는지 확인하기 (기본 git 명령)

# 지금 추적 중인지
git ls-files | grep settings.local.json

# 과거 커밋에 있었는지
git log --all --oneline -- .claude/settings.local.json

2. 올라가 있다면 — 순서가 중요합니다

  • 먼저 비밀번호·키를 바꾸세요(로테이션). 파일을 지우거나 히스토리를 고쳐도, 이미 누군가 복사했거나 포크에 남아 있을 수 있어요. 보도들이 공통으로 강조한 첫 단계입니다.
  • 그다음 추적을 멈추고 레포의 .gitignore에 추가합니다. 이렇게 하면 팀원·다른 클론에도 규칙이 적용돼요.
git rm --cached .claude/settings.local.json
echo ".claude/settings.local.json" >> .gitignore
  • 팀이 공유하는 .claude/settings.json에도 비밀값이 든 allow 규칙이 없는지 같이 보세요.

3. 앞으로 — 명령에 비밀번호가 들어가지 않게

  • “다시 묻지 않기"를 누르기 전에 명령 안에 비밀번호·토큰이 있는지 한 번 읽어 보세요. 있다면 그 명령은 한 번만 승인하세요.
  • 비밀번호는 명령에 직접 쓰지 말고 환경 변수나 비밀값 관리 도구(secret manager)를 거치게 하세요.
  • 공식 문서에는 에이전트가 .env 파일을 읽지 못하게 막는 deny 규칙 예시도 있습니다. 비밀번호를 읽지 못하면 명령에 넣을 수도 없어요.
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)"
    ]
  }
}
  • 팀이라면 커밋 전·CI 단계에 비밀값 스캐너를 두되, .claude/ 같은 에이전트 폴더도 검사 대상에 넣고, 패턴이 없는 평범한 비밀번호는 놓칠 수 있다는 점을 기억하세요.

정리

  • Claude Code의 “다시 묻지 않기"는 승인한 명령을 문자 그대로 .claude/settings.local.json에 저장하고, 명령에 비밀번호가 있으면 그것도 함께 저장됩니다.
  • 기본 보호막(전역 git excludes)은 내 컴퓨터에만 적용돼서, 다른 환경·이미 추적 중인 파일에서는 막지 못했습니다.
  • Apiiro 조사에서 공개 레포 1,994곳, 비밀값 2,539개가 나왔고, 평범한 비밀번호는 스캐너도 상당수 놓쳤습니다.
  • 할 일: 확인 → 로테이션 → 추적 중단과 .gitignore → 명령에 비밀번호 넣지 않기. 편의 버튼 하나가 무엇을 저장하는지 아는 것이 첫걸음입니다.
