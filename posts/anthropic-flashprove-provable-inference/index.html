AI 답변에 '이 모델이 썼다'는 영수증을 붙인다, Anthropic FlashProve 정리

Anthropic이 영지식 증명으로 'AI 답변이 약속한 그 모델에서 나왔다'를 검증하는 오픈소스 프로토타입 FlashProve를 공개했습니다. 작동 원리와 수치, 아직 남은 한계를 정리합니다.

2026년 11월 2일, Anthropic이 「Progress on provable inference for large language models」라는 연구 글과 함께 FlashProve를 오픈소스로 공개했습니다. AI API가 돌려준 답변이 정말 제공자가 약속한 그 모델에서 나왔는지를 암호학적으로 증명하는 연구용 프로토타입이에요. 긱뉴스와 여러 보안 매체에서 다뤄졌습니다.

이 글은 Anthropic의 원문과 Help Net Security, The Next Web 보도를 교차 확인해 정리했습니다. 이 블로그의 자동 초안은 Anthropic의 모델(Claude)이 작성하므로, 이해관계가 있을 수 있다는 점을 미리 밝혀 둡니다.

무슨 문제를 풀려는 걸까

지금은 API로 AI를 쓸 때 어떤 모델이 답했는지 확인할 방법이 없습니다. 답변 품질만으로는 구분이 잘 안 되죠. 원문이 든 상황은 이렇습니다.

  • 라우팅 서비스(여러 AI 모델을 묶어 파는 중개 서비스)가 몰래 더 싼 모델로 바꿔치기할 수 있습니다.
  • 서버가 뚫리면 공격자가 답변 내용을 중간에 조작할 수 있습니다.
  • 외부 평가 기관은 자기가 시험한 모델이 실제 서비스되는 모델과 같은지 확인하기 어렵습니다.
  • 규제 기관이 “승인된 모델만 서비스되고 있는지” 확인할 수단도 마땅치 않습니다.

먼저 용어 세 가지

  • 영지식 증명(Zero-Knowledge Proof): 비밀을 하나도 보여 주지 않고 “나는 그 비밀을 알고 있다"거나 “이 계산은 맞다"를 증명하는 암호 기법입니다. 여기서는 모델 가중치(비밀)를 공개하지 않고 “이 가중치로 계산한 결과가 이 답변"임을 증명합니다.
  • zkSNARK: 영지식 증명 중에서도 증명이 작고 확인이 빠른 방식입니다. 확인하는 쪽(검증자)은 큰 계산을 다시 돌리지 않아도 돼요.
  • 커밋먼트(commitment): 값을 봉인한 “지문” 같은 것입니다. 나중에 값을 바꾸면 들통나지만, 지문만 봐서는 원래 값을 알 수 없어요. 제공자가 가중치의 커밋먼트를 먼저 공개해 두는 게 출발점입니다.

어떻게 동작하나

단계하는 일
오프라인 (모델당 1번)제공자가 모델 가중치의 커밋먼트를 공개합니다. 가중치 자체는 숨깁니다.
온라인 (요청마다)제공자가 “커밋한 모델이 이 프롬프트에 이 답변을 낸다"는 증명을 만듭니다.
검증누구나 커밋먼트·프롬프트·답변·증명만으로 확인합니다. 가중치나 GPU가 필요 없습니다.

원문에 따르면 이 시스템은 정직한 증명은 통과하고(완전성), 위조는 사실상 불가능하며(건전성), 가중치나 어떤 전문가 층이 돌았는지 같은 정보는 드러내지 않는(영지식) 성질을 목표로 합니다. 해시 함수 기반으로 만들어 양자 컴퓨터 이후에도 안전한 설계를 노렸다고 해요.

속도를 끌어올린 비결도 소개합니다.

  • 전문가 혼합(MoE) 구조 활용: 실험 모델은 전체 4,000억 개 파라미터 중 토큰마다 약 170억 개만 쓰는 구조라, 증명 작업도 실제로 쓰인 부분만큼만 합니다.
  • 사후 일괄 증명: 답변을 먼저 내보내고, 나중에 요청 여러 개를 묶어서 증명합니다.
  • GPU 1장으로: 가중치를 호스트 메모리에서 층 단위로 흘려 넣어 GPU 한 장에서 돌아가게 했습니다.

숫자로 보면

실험 대상은 Meta의 공개 모델 Llama 4 Maverick(4비트 변환본)입니다. 아래 수치는 원문과 보도에서 공통으로 확인된 것만 옮겼습니다.

항목수치
증명 환경H100 GPU 1장 + CPU 24코어
오프라인 커밋약 39분, 1번으로 약 1,600만 요청 처리
증명 속도약 110 토큰/초 (24개 요청 묶음 약 223초)
증명 크기요청당 약 18.78MB (1,024 토큰 범위)
검증 시간CPU 24스레드 약 17초, 1스레드 약 21초
검증자가 받는 것커밋먼트 약 6.5MB + 요청당 증명 1개
일반 추론 대비 비용GPU 시간 기준 평균 약 72배, 최대 부하에서 약 94배

비교 대상으로 원문은 같은 모델을 증명한 이전 연구가 1,000토큰에 14.3시간 걸렸다고 소개합니다. 수십~백 배의 오버헤드가 여전히 크지만, “이론상 가능"에서 “GPU 한 장으로 실험 가능” 수준까지 왔다는 게 이번 발표의 의미예요.

또 하나 눈에 띄는 점은 형식 검증입니다. 증명 도우미 Lean(수학 증명을 컴퓨터가 검사해 주는 언어)으로 보안 성질을 기계적으로 증명했고, 느리지만 엄밀한 Lean 검증기와 일상용 C++ 검증기를 함께 냈습니다.

아직 남은 한계

원문이 스스로 밝힌 한계가 꽤 많습니다. 실무에 바로 쓸 물건은 아니라는 뜻이에요.

  • 문맥 길이 1,024토큰: 요즘 챗봇이 쓰는 문맥보다 훨씬 짧습니다.
  • MoE 구조 전제: 다른 구조의 모델에는 아직 적용되지 않습니다. 모델 구조(아키텍처)도 검증자에게 드러납니다.
  • 정수 모델·그리디 디코딩 기준: 증명은 가중치의 정수 버전이 “가장 확률 높은 토큰"을 골랐다는 것만 보장합니다. 실제 서비스처럼 부동소수점 계산이나 무작위 샘플링을 쓰면 결과가 달라질 수 있고, 악의적으로 설계된 프롬프트는 범위 밖입니다.
  • 코드와 증명의 간극: 논문·Lean 프로토콜·실제 빠른 코드가 서로 정확히 일치한다는 보장은 없습니다. 증명 생성기(prover)는 형식 검증되지 않았고, C++ 검증기도 테스트에서 Lean 검증기와 결과가 일치했을 뿐 형식 보장은 없습니다.
  • 부채널 공격 제외: 응답 시간 측정 같은 방법으로 가중치 정보가 새는 문제는 다루지 않습니다.

또 이 기술이 증명하는 건 “이 모델이 이 답을 냈다"까지입니다. 답변 내용이 맞는지, 안전한지는 별개의 문제예요. 원문도 하드웨어가 몰래 다른 작업(예: 학습)을 함께 하지 않는다는 것까지 증명하지는 않는다고 밝힙니다.

독자가 해 볼 것

  • 개념 공부용으로 좋습니다. 영지식 증명을 들어만 봤다면, 실제 대형 시스템에 어떻게 쓰이는지 보여 주는 좋은 사례예요. 원문 글의 구성(문제 → 성질 → 구조 → 한계)을 따라 읽어 보길 권합니다.
  • 코드 둘러보기: 저장소 anthropics/FlashProve는 Apache 2.0 라이선스이고 증명기, C++·Lean 검증기, 프로토콜 명세, Lean 정리 시각화 도구가 들어 있습니다. 모델 가중치는 포함되지 않아 Hugging Face에서 Meta 라이선스에 따라 따로 받아야 합니다. 실행 방법은 저장소의 공식 안내를 따르세요(이 글에서는 직접 실행해 보지 않았습니다).
  • AI 서비스를 고르는 입장이라면: 지금 당장은 “어떤 모델이 답했는지"를 제공자의 말에 의존할 수밖에 없다는 점을 기억해 두세요. 중개 서비스를 쓸 때 모델 표기·과금 내역을 확인하는 습관이 현재로선 현실적인 대비입니다.

정리

  • FlashProve는 AI 답변에 “약속한 모델이 이 답을 냈다"는 암호학적 영수증을 붙이는 연구용 프로토타입입니다.
  • GPU 한 장으로 4,000억 파라미터 MoE 모델의 답변을 증명했다는 점은 큰 진전이지만, 일반 추론보다 70~95배 비싸고 문맥은 1,024토큰에 그칩니다.
  • 당장 쓰는 기술이라기보다, AI 공급망 신뢰를 소프트웨어로 검증하는 방향이 현실화되고 있다는 신호로 보는 게 맞습니다.
