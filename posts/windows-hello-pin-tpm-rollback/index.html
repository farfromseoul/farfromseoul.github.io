노트북 잠금 화면에 넣는 4자리 PIN은 비밀번호보다 훨씬 짧습니다. 그래도 안전하다고 여겨진 이유는 “몇 번 틀리면 한동안 더 못 넣게 막는” 잠금 장치가 있어서입니다. 그런데 이 잠금 장치가 기억하는 “틀린 횟수"를 예전 값으로 되돌리는 공격이 공개됐습니다. 독일 베를린 공과대학교(TU Berlin) 연구진의 논문 「Hello Again」입니다.

논문 원문(arXiv, 2026-11-13 게재, ACM CCS ‘26 발표 논문의 수정판), AMD 공식 보안 공지(AMD-SB-7079, 2026-11-17), The Hacker News·PC Games Hardware 보도를 교차 확인해 썼습니다. (2026-11-19 확인 기준)

무슨 일이 있었나

  • 연구진은 2015~2025년에 나온 PC 9대를 조사해, 펌웨어 TPM의 잠금 기록을 되돌려 PIN을 무제한에 가깝게 시도하는 방법을 보였습니다.
  • 잠긴 상태의 실제 노트북에서 끝까지 시연했고, 논문 기준 최악의 경우 4자리 Windows Hello PIN은 69일 → 40시간, 기본 6자리 BitLocker 부팅 PIN은 19년 → 20일로 줄었습니다.
  • AMD는 펌웨어 결함을 인정하고 CVE-2026-43613(CVSS 4.0 기준 5.1)을 발급했습니다. 패치는 2026년 11월~2027년 2월에 순차 배포 예정입니다.
  • Microsoft는 “중간(moderate) 심각도"로 분류하고 CVE는 발급하지 않았으며, 권장 최소 Hello PIN 길이를 6자리로 올리겠다고 연구진에게 밝혔습니다.

중요한 전제부터 짚겠습니다. 이 공격은 PC를 손에 넣고 메인보드를 열어 칩에 장비를 연결해야 합니다. 원격으로 되는 공격이 아닙니다. 대신 노트북 분실·도난, 잠깐 자리를 비운 사이의 접근, 출장지 호텔 같은 상황에서는 현실적인 위협이 됩니다.

핵심 개념 먼저

용어한 줄 풀이
TPM암호 키를 보관하고, PIN을 너무 많이 틀리면 막아 주는 보안 칩(또는 기능)
fTPM (펌웨어 TPM)별도 칩 없이 CPU 안의 보안 프로세서가 TPM 역할을 하는 방식. 요즘 x86 PC 대부분이 사용
안티해머링(anti-hammering)틀린 횟수를 세어 일정 횟수를 넘으면 시도를 막는 장치. 논문 기준 32회 실패 시 잠김
SPI 플래시메인보드에 붙은 작은 저장 칩. BIOS/UEFI와 fTPM의 저장 상태가 여기에 들어감
롤백(rollback)저장된 상태를 예전 복사본으로 덮어써 되돌리는 것
RPMC플래시 칩 안의 “올라가기만 하는 카운터”. 롤백을 알아채기 위한 JEDEC 표준 기능
인터포저(interposer)칩과 보드 사이에 끼워 신호를 엿보거나 바꾸는 작은 기판

fTPM은 전용 저장 공간이 없어서, 틀린 횟수 같은 상태를 암호화해 메인보드의 SPI 플래시에 저장합니다. 암호화돼 있어도 “예전 파일을 통째로 다시 써 넣는” 롤백은 내용을 몰라도 할 수 있습니다. 그래서 최근 PC는 RPMC로 “지금 상태가 최신인지"를 확인합니다. 이번 연구는 바로 이 RPMC 확인이 실제 제품에서 제대로 동작하지 않는다는 점을 파고들었습니다.

공격은 어떻게 동작하나

흐름은 단순합니다.

  1. 플래시에 저장된 fTPM 상태를 복사해 둡니다.
  2. PIN을 몇 번 틀려 봅니다(틀린 횟수가 올라감).
  3. 복사해 둔 예전 상태를 다시 써 넣어 틀린 횟수를 0으로 되돌립니다.
  4. 1~3을 반복합니다.

PC가 3번의 되돌림을 알아채지 못하면 잠금은 사실상 사라집니다. 연구진이 찾은 “알아채지 못하는” 경우는 다음과 같습니다.

경우무엇이 문제인가연구진이 확인한 결과
AMD + RPMC 플래시AMD 보안 프로세서 펌웨어가 카운터가 실제로 올라갔는지 다시 확인하지 않음. 인터포저가 증가 명령을 막고 “성공"으로 응답하면 속음HP OmniBook 3(Ryzen AI 5 330)에서 Windows Hello PIN 공격 시연
AMD + RPMC 없는 플래시롤백을 막는 장치 자체가 없어 보임조사한 AMD 데스크톱 2대에서 일반 플래시 기록기로 예전 이미지를 다시 쓰자 잠금 기록이 초기화됨
Winbond RPMC 플래시 (CPU 무관)전압을 순간적으로 흔드는 “전압 글리칭"으로 카운터 서명용 HMAC 키가 새어 나옴. 키가 있으면 카운터 값을 위조 가능Framework Laptop 13(Intel Core Ultra 5 125H)에서 BitLocker PIN 공격 시연
Intel + RPMC 없는 플래시Intel 보안 엔진(CSME)이 자체 카운터를 사용조사한 3대 모두 단순 롤백을 탐지함 (논문의 다른 공격은 이 구성에 해당하지 않음)

Winbond는 NOR 플래시 시장의 25% 이상을 차지한다고 논문은 설명합니다. 즉 CPU 회사와 상관없이 어떤 플래시 칩이 붙어 있느냐도 영향 범위를 가릅니다. Microsoft Pluton을 TPM으로 쓰는 PC도 같은 방식으로 영향을 받을 것으로 연구진은 예상하지만, 직접 시험하지는 않았습니다.

출처: 논문(arXiv 2611.18126) 초록과 The Hacker News·PC Games Hardware 보도에서 같은 값으로 확인한 수치만 실었습니다.

표에서 보이듯 자릿수를 두 자리만 늘려도 시간이 100배 가까이 늘어납니다. 이번 공격은 “틀린 횟수 제한"을 없앨 뿐 PIN 자체를 푸는 계산을 빠르게 하는 것은 아니기 때문입니다.

PIN이 뚫리면 잠금 화면만 열리는 게 아닙니다. 논문은 그 PC에 묶인 키, Windows Hello 기반 회사 SSO(한 번 로그인으로 여러 서비스 접속)까지 이어질 수 있다고 설명합니다. BitLocker의 TPM+PIN 방식은 “TPM만 쓰는 것보다 안전하니 PIN을 추가하라"는 권고의 근거였는데, 그 PIN 역시 같은 잠금 장치에 기대고 있어 함께 약해집니다.

각 회사의 반응

회사반응
AMD펌웨어 결함 인정, CVE-2026-43613(CVSS 5.1) 발급. “물리 공격은 위협 모델 밖"이라면서도 RPMC는 이런 인터포저 공격을 막기 위한 것이라고 설명. Ryzen·Ryzen AI·Threadripper·Athlon·EPYC 계열 패치를 2026년 11월~2027년 2월에 배포 예정, 일부 제품은 일정 미정
IntelIntel 부품 자체의 취약점이 증명된 것은 아니라는 입장. 물리 접근·추가 장비·취약한 플래시 구현이 필요하다고 설명
Microsoft2026년 4월 제보받음. 중간 심각도로 분류, CVE·즉시 수정 없음. 권장 최소 Hello PIN을 6자리로 올리겠다고 약속
Winbond문제를 검토 중이나 수정 여부·일정은 밝히지 않음. 칩 설계 자체를 바꿔야 하는 문제

한계와 주의할 점

  • 물리 접근이 필수입니다. 보드를 열고 플래시 칩을 떼어 내거나 장비를 연결해야 하고, 화면을 읽고 PIN을 넣는 자동화 장치까지 필요합니다. 원격 해킹이나 악성코드로 할 수 있는 공격은 아닙니다.
  • 시간 수치는 추정치입니다. 연구진은 실제로 236번 시도해 PIN을 찾았고(시연용으로 고른 PIN), 전체 조합에 걸리는 시간은 그 속도로 계산했습니다.
  • 조사 대상은 9대입니다. “RPMC 없는 AMD PC는 보호가 없다"는 결론도 데스크톱 2대 결과라 모든 AMD PC를 대표한다고 단정할 수는 없다고 연구진 스스로 적었습니다.
  • AMD 패치가 근본 해결은 아닙니다. AMD 공지는 RPMC가 있는 플래시에서 증가 확인 결함을 다루며, RPMC가 없는 AMD PC나 Winbond 칩 문제는 다루지 않습니다.
  • 일부 보도는 시험한 Intel PC의 결과를 다르게 정리하기도 했습니다. 이 글은 논문의 시스템 표를 기준으로 썼습니다.

지금 할 일

개인 사용자

  • Windows Hello PIN을 6자리 이상, 가능하면 8자리 이상으로 바꾸세요. 설정 → 계정 → 로그인 옵션 → PIN(Windows Hello) → PIN 변경에서 바꿀 수 있고, 문자·기호를 넣는 옵션도 있습니다.
  • AMD PC라면 노트북·메인보드 제조사의 BIOS/펌웨어 업데이트 공지를 확인하고, 나오는 대로 설치하세요. AMD 칩 업데이트는 PC 제조사를 거쳐 배포됩니다.
  • 노트북을 차 안·카페 등에 두고 자리를 비우지 마세요. 이 공격은 “기기를 몇 시간~며칠 확보한 사람"이 전제입니다.

회사 IT·보안 담당자

  • Windows Hello for Business의 Minimum PIN length 정책(그룹 정책: 컴퓨터 구성 → 관리 템플릿 → 시스템 → PIN Complexity)을 확인하세요. 설정하지 않으면 6자리가 기본이지만, 4자리로 낮춰 둔 조직이 있습니다.
  • BitLocker를 TPM+PIN으로 쓴다면 Configure minimum PIN length for startup 정책을 6자리보다 길게 올리고, 문자·기호를 허용하는 Allow enhanced PINs for startup도 검토하세요.
  • 자산 목록에서 AMD 기반 노트북을 추리고, 제조사별 펌웨어 배포 일정을 추적하세요.
  • 분실·도난 신고 절차에 “해당 기기에 묶인 Hello 자격 증명·인증서 폐기"가 들어 있는지 점검하세요.

정리

짧은 PIN의 안전은 “몇 번만 틀릴 수 있다"는 잠금 장치에 전적으로 기대고 있었습니다. 이번 연구는 그 잠금 기록이 메인보드의 플래시 칩에 있고, 실제 제품에서 되돌림을 제대로 막지 못하는 경우가 있다는 점을 보여 줬습니다. 물리 접근이 필요해 당장 대규모 피해로 이어질 공격은 아니지만, 대응은 간단합니다. PIN을 길게, 펌웨어는 최신으로, 기기는 손에서 놓지 않기.
