Gemini 4 Hydrogen 출시: 3.8 Flash를 대체하는 실행용 모델, 옮기기 전에 바뀌는 API 설정 7가지

구글이 코딩·에이전트 작업용 빠른 모델 Gemini 4 Hydrogen을 내놓았습니다. 가격·제공 범위, 구글 발표와 독립 평가(Artificial Analysis)의 성능 차이, 그리고 3.8 Flash에서 옮길 때 에러가 나는 파라미터를 정리합니다.

2026-11-13 · #llm #ai-model #gemini #google #api-migration #benchmark

2026년 11월 12일(미국 시간), 구글이 Gemini 4 제품군에 Gemini 4 Hydrogen을 추가했습니다. 핵심만 먼저 정리하면 이렇습니다.

  • 깊은 추론은 상위 모델(Carbon·Argon)에 맡기고, Hydrogen은 **코드 수정·테스트 실행 같은 “빠른 실행”**을 맡는 모델입니다. 구글은 Gemini 3.8 Flash의 후속으로 소개합니다.
  • API 가격은 100만 토큰당 입력 $1.50 / 출력 $7.50, 컨텍스트는 약 100만 토큰입니다.
  • 구글 발표로는 상위 모델 Argon보다 종합 점수가 1점 높지만, 독립 평가에서는 경쟁 모델보다 약간 낮고, 에이전트형 터미널 작업 점수는 구글 발표보다 낮게 나왔습니다.
  • 3.8 Flash에서 옮길 때는 기본 추론 수준이 바뀌고, 몇몇 파라미터는 아예 400 에러가 납니다. 이 부분이 개발자에게 가장 실질적인 변화입니다.

먼저 밝혀 둡니다. 이 초안은 Anthropic의 AI 모델(Claude Opus 5.5)이 작성했고, 아래 비교에는 Anthropic 모델(Claude Sonnet 5.5)도 등장합니다. 그래서 수치는 구글 공식 발표(①)와 독립 평가(②)를 나눠 적었고, 둘 이상의 출처에서 확인한 것만 실었습니다.

먼저 용어 몇 가지

  • 추론 수준(thinking level): 모델이 답하기 전에 얼마나 오래 “생각"할지 정하는 설정. 높을수록 정확해지지만 토큰(=비용)과 시간이 더 듭니다. Hydrogen은 low·medium·high·xhigh 네 단계입니다.
  • 컨텍스트 윈도: 모델이 한 번에 다룰 수 있는 글자 양(토큰 수). 입력과 출력이 함께 씁니다.
  • 에이전트(agentic) 작업: 모델이 터미널 명령 실행·파일 수정·테스트처럼 여러 단계를 스스로 이어 가는 작업.
  • 암묵적 캐싱(implicit caching): 같은 앞부분(프롬프트 접두사)을 반복해 보내면 자동으로 재사용해 값을 깎아 주는 기능.
  • Terminal-Bench: 모델이 터미널에서 실제 과제를 풀게 하는 에이전트 벤치마크. 버전(4.0, 4.1)마다 문제가 달라 서로 비교하면 안 됩니다.

함께 나온 Orchestrator는 Antigravity 안에서 한 작업 도중 모델을 갈아 끼우는 기능입니다. Carbon이 코드를 읽고 계획을 세우면 Hydrogen이 수정·패키지 업데이트·테스트를 하고, 막히면 다시 Carbon에게 넘깁니다. 처음에는 Google AI Ultra 구독자만 쓸 수 있습니다.

표를 읽을 때 볼 점:

  • “Argon보다 높다"는 1점 차이입니다. 그것도 기본값 high 기준이고, 추론 수준을 medium으로 내리면 41로 크게 떨어집니다.
  • Terminal-Bench 57%(구글)와 54%(독립 평가)는 서로 다른 버전(4.1 vs 4.0)이라 직접 비교할 수 없습니다. 구글 발표 안에서도 Orchestrator 결과의 버전 표기가 글마다 4.0·4.1로 다릅니다.
  • 독립 평가에서 xhigh로 올려도 Terminal-Bench 점수는 그대로인데, 과제당 비용은 $1.87 → $3.16으로 올랐습니다. 무조건 최고 수준으로 돌리는 게 답은 아닙니다.
  • 2.5배 빠름, 환각 감소 같은 수치는 이전 세대 3.8 Flash와 비교한 것이지 경쟁사 모델과 비교한 것이 아닙니다.

3.8 Flash에서 옮길 때 바뀌는 API 설정 7가지

여기부터는 Google Cloud의 Gemini 4 Hydrogen 개발자 가이드 기준입니다. Gemini API(AI Studio)를 쓴다면 같은 동작인지 해당 문서에서 한 번 더 확인하세요.

#바뀐 점그냥 두면
1모델 ID를 gemini-4-hydrogen으로 변경—
2기본 thinking_level이 MEDIUM → HIGH응답이 느려지고 토큰이 더 듦. 이전 속도를 원하면 MEDIUM을 직접 지정
3thinking_budget, MINIMAL 지원 중단HTTP 400 에러. thinking_level로 바꿔야 함
4temperature, top_p, top_k에러는 없지만 무시됨
5frequency_penalty, presence_penalty, 1보다 큰 candidate_countHTTP 400 에러
6명시적 캐싱(cached_content) 미지원제거 필요. 대신 4,096 토큰 이상 같은 접두사는 자동 캐싱(3.8 Flash는 6,144)
7출력 기본 한도 65,536 토큰, 입력·출력 합산 1,048,576 토큰긴 출력은 한도를 고려해 설계

추가로, 여러 턴 대화에서는 응답에 담긴 thought_signature를 다음 요청에 그대로 넘겨야 합니다. 앞선 대화를 요약·편집해서 보내는 앱이라면 문서가 안내하는 prefix_mismatch_behavior 설정을 확인하세요.

공식 문서에 실린 추론 수준 지정 예시(Python, Google Cloud 환경)입니다.

from google import genai
from google.genai import types

client = genai.Client(enterprise=True, project="PROJECT_ID", location="global")

response = client.models.generate_content(
    model="gemini-4-hydrogen",
    contents="Design a lock-free ring buffer in Rust for multi-producer, single-consumer telemetry ingestion.",
    config=types.GenerateContentConfig(
        thinking_config=types.ThinkingConfig(
            thinking_level="HIGH",  # Default: "HIGH" (Valid: "LOW", "MEDIUM", "HIGH", "XHIGH")
        ),
    ),
)
print(response.text)

PROJECT_ID는 본인 Google Cloud 프로젝트 ID로 바꿉니다. AI Studio API 키로 쓰는 경우 클라이언트 생성 방식이 다르니 AI Studio 문서를 따르세요.

한계·주의할 점

  • 성능 수치 대부분이 구글 자체 측정입니다. 독립 평가가 나온 항목(지능 지수, Terminal-Bench 4.0)에서는 구글 발표보다 덜 돋보이는 결과도 있습니다.
  • 독립 평가 기준으로 Claude Sonnet 5.5·GPT-6.1 Sol보다 종합 점수는 약간 낮습니다. 대신 Sonnet보다 싸고, 더 싼 모델들보다는 점수가 높아 “가격 대비” 위치가 강점입니다.
  • xhigh는 비용이 크게 늘어납니다. 작업에 따라 점수가 오르지 않을 수도 있으니 작은 샘플로 먼저 비교해 보세요.
  • Orchestrator는 아직 Ultra 구독자 전용이고, Carbon과 비교한 수치는 “가깝다"는 표현뿐이라 정확한 차이는 알 수 없습니다.
  • 출시 직후라 장기 사용 후기나 대규모 독립 벤치마크(예: LMArena 순위)는 아직 쌓이지 않았습니다.

AI를 처음 써 보는 학생·취준생이라면

  • 따로 할 일은 없습니다. Google 검색과 Gemini 앱(무료는 자동 선택)에서 이미 쓰이고 있습니다.
  • 코딩 과제에 쓸 때는 “구글이 Argon보다 낫다고 했다"보다, 같은 질문을 다른 모델과 나란히 돌려 보고 결과를 직접 비교하는 습관이 더 쓸모 있습니다.

3.8 Flash를 API로 쓰고 있는 개발자라면

  1. 코드에서 thinking_budget, MINIMAL, frequency_penalty, presence_penalty, cached_content를 검색해 먼저 정리합니다. 남아 있으면 400 에러가 납니다.
  2. 기존 응답 속도·비용을 유지하고 싶다면 thinking_level을 MEDIUM으로 명시하고 시작합니다.
  3. 실제 업무 프롬프트 몇십 개로 medium·high를 나란히 돌려 정확도와 토큰 사용량을 비교한 뒤 기본값을 정합니다.
  4. 프롬프트의 고정 부분(시스템 지시, 문서)을 앞쪽에 두면 자동 캐싱을 더 잘 받습니다.

모델을 고르는 중인 팀이라면

  • 가장 어려운 설계·분석은 상위 모델, 반복적인 수정·테스트는 Hydrogen 같은 실행용 모델로 나누는 구성이 구글의 Orchestrator 방향과 같습니다. 다른 회사 모델로도 같은 구성이 가능하니, 비용표와 독립 평가를 함께 놓고 판단하세요.

정리

Gemini 4 Hydrogen은 “제일 똑똑한 모델"이라기보다 값과 속도를 맞춘 실행용 모델입니다. 구글 발표의 “Argon보다 높다"는 1점 차이이고, 독립 평가에서는 경쟁 모델보다 약간 낮지만 가격 대비 위치는 좋습니다. 지금 3.8 Flash를 쓰고 있다면 성능 비교보다 먼저 기본 추론 수준 변경과 400 에러가 나는 파라미터부터 점검하는 것이 할 일입니다.
