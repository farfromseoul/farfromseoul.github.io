지난 Fireworks AI 2차 침해 글에서 “Cursor 쪽 피해는 아직 공식 확인된 내용이 없다"고 적었습니다. 그 답이 나왔습니다. Cursor는 11월 13일 사고 경과 보고에서, 10월 29일 자사 확장 마켓에 가짜 Claude Code 확장이 올라간 사건의 출발점이 Cursor가 Fireworks AI에 발급해 둔 접근 키였다고 밝혔습니다.

하청업체에서 샌 키 하나가 몇 단계를 거쳐 개발자 PC에 SSH 백도어를 심는 시도로 이어진 사례입니다. Cursor를 안 쓰더라도, AI 코딩 도구·확장 프로그램을 쓰는 사람이라면 볼 만한 사고입니다.

Cursor에 따르면 10월 29일 해당 버전을 받은 사람은 최대 5,000명입니다. 영향을 받은 것은 Windows·macOS용 빌드이고, Cursor는 이 두 버전이 “Anthropic이 만든 것이 아니다"라고 밝혔습니다. Anthropic 쪽도 자사 시스템이 뚫린 것이 아니며 공식 배포 채널의 버전은 영향이 없다고 CSO Online에 밝혔습니다.

먼저 용어 몇 가지

  • 확장 마켓(Extension Marketplace): VS Code 계열 편집기에서 확장 프로그램을 내려받는 저장소. Cursor는 VS Code를 바탕으로 만든 AI 편집기라 자체 마켓(과 그 앞단 캐시)을 운영합니다.
  • 캐시(cache): 원본 대신 빠르게 파일을 내주려고 복사본을 두는 서버. 여기에 파일을 바꿔 넣으면 사용자는 정상 업데이트로 알고 받습니다.
  • 에이전트 트레이스(trace): AI 코딩 에이전트가 작업하면서 남긴 대화·명령·결과 기록. 사용자가 붙여 넣은 키나 비밀번호가 그대로 남기도 합니다.
  • SSH 백도어: 공격자의 SSH 공개키를 authorized_keys(이 키를 가진 사람은 비밀번호 없이 접속 허용) 파일에 몰래 넣어, 나중에 원격으로 들어올 길을 만드는 것.
  • 리버스 터널(reverse tunnel): 피해 PC가 먼저 공격자 서버로 접속을 열어, 방화벽 안쪽 PC에 공격자가 거꾸로 들어올 수 있게 하는 연결.
  • 지속성(persistence): 재부팅이나 프로그램 삭제 뒤에도 악성 코드가 다시 실행되도록 시작 항목·예약 작업 등을 심는 것.

                           └─ 사용자에게 "정상 업데이트"로 배포

복사된 트레이스는 프라이버시 모드(Privacy Mode)를 켜지 않은 세션 것으로, 대부분 2025년 기록이었고 모델 학습에 쓰도록 허용된 데이터였다고 합니다. 트레이스 속 자격 증명이 노출된 고객은 전체의 0.01% 미만이라고 Cursor는 밝혔습니다.

공격자가 SaaS 도구를 통해 접근한 것으로 Cursor가 밝힌 범위는 다음과 같습니다.

접근된 것영향 없다고 밝힌 것

2. 악성 확장은 무엇을 했나

Cursor 보안 공지와 보도를 종합하면, 악성 코드는 확장의 extension.js 맨 앞에 들어가 있어 확장이 로드되자마자 사용자 조작 없이 실행됐습니다.

단계한 일
정보 수집호스트 이름, 사용자 이름, OS, 홈·작업 디렉터리, Git 이메일, 공인 IP, 환경 변수 이름(값은 아님)을 공격자 서버로 보냄
백도어authorized_keys에 공격자 키(주석 svc-telemetry) 추가, 로컬 SSH 서비스 켜기 시도, 리버스 터널 열기
지속성macOS: LaunchAgent(com.apple.sysmond.plist) / Windows: 예약 작업 SysMon, 시작 프로그램 / Linux: cron @reboot. 공통으로 ~/.config 아래 스크립트
재시도약 60초마다 터널 연결 재시도

Cursor는 SSH 서비스를 켜는 단계는 관리자 권한이 없으면 대개 실패하지만, 키 추가·지속성 설치·정보 전송은 그래도 일어날 수 있다고 했습니다. 또 확장 폴더 밖에 스크립트를 두기 때문에 확장을 지우는 것만으로는 부족하다고 강조했습니다. 공격자 서버는 현재 내려가 있다고 합니다.

3. Cursor가 한 조치

  • Fireworks에 발급한 키 폐기, 추론 트래픽을 Fireworks에서 모두 옮기고 공유 데이터 접근 차단
  • 자격 증명 폐기·교체, 추가 침입 흔적 조사
  • 악성 빌드 삭제, 마켓을 잠시 내리고 다시 구축
  • 2.1.312·2.1.313 설치자에게 개별 통보, 노출된 자격 증명 폐기 지원

한계와 주의할 점

  • 두 번째 단계의 세부는 아직 공개되지 않았습니다. 어떤 SaaS 도구에서 어떤 자격 증명으로 마켓 캐시에 쓸 수 있었는지는 Cursor 보고에 자세히 나오지 않습니다.
  • 수치는 모두 Cursor 발표 기준입니다(최대 5,000명, 0.01% 미만). 독립 조사 결과는 아직 없습니다.
  • Fireworks 쪽 침해 경위는 지난 글 시점 이후 새로 확인된 내용이 많지 않습니다. 같은 사고로 다른 회사들도 영향을 받았다는 보도가 있지만, 여기서는 회사가 직접 밝힌 내용만 다룹니다.
  • 정상 Claude Code 확장(Anthropic 공식 배포)이나 VS Code 공식 마켓의 버전이 영향을 받았다는 근거는 없습니다.

독자가 할 일

Cursor에서 Claude Code 확장을 쓴다면

  1. 10월 29일 전후로 2.1.312나 2.1.313을 받았는지 확인합니다. Cursor에서 통보 메일을 받았는지도 봅니다.
  2. Cursor 공지가 안내한 대로 authorized_keys에 svc-telemetry라는 문자열이 있는지 찾습니다. macOS는 ~/.ssh/authorized_keys, Windows는 %USERPROFILE%\.ssh\authorized_keys와 C:\ProgramData\ssh\administrators_authorized_keys가 대상입니다. 보안업체 Phorion은 주석 문자열만 믿지 말고 키 지문(fingerprint)까지 대조하라고 권했습니다. 지문과 해시 목록은 Cursor 공지에 있습니다.
  3. 흔적이 있으면 Cursor가 공지에 올린 점검·제거 스크립트를 공지의 안내대로 실행하고, 그 PC는 격리한 뒤 다시 설치할지 판단합니다.
  4. 그 PC에서 접근할 수 있던 자격 증명은 모두 교체합니다. Git 토큰, 클라우드 키, .env 속 API 키 등입니다. 교체는 깨끗한 다른 기기에서 합니다.

Cursor 지원팀이나 에이전트 대화에 키를 붙여 넣은 적이 있다면

  • 그 키는 이미 노출됐다고 보고 폐기·재발급합니다. 이번 사고의 2차 피해는 바로 트레이스와 지원 문의에 남은 키에서 시작됐습니다.
  • 학습 데이터 제공을 원하지 않으면 프라이버시 모드를 켜 둡니다.

팀에서 개발 도구를 관리한다면

  • 확장 프로그램도 공급망으로 다룹니다. 허용 목록(allowlist), 자동 업데이트 대신 검토 후 업데이트, 개발 PC의 외부 연결 모니터링을 검토합니다.
  • 협력업체에 주는 키는 짧은 수명·최소 권한으로 발급하고, 대량 읽기 같은 이상 사용을 감시합니다.
  • AI 에이전트 로그·트레이스에는 비밀값을 가려서(redaction) 저장합니다.

정리

  • 10월 29일 Cursor 확장 마켓에 SSH 백도어를 심는 가짜 Claude Code 확장(2.1.312·2.1.313)이 약 11시간 올라왔고, 최대 5,000명이 받았을 수 있습니다.
  • 출발점은 Cursor가 하청업체 Fireworks AI에 준 접근 키였고, 에이전트 트레이스에 남은 자격 증명이 다음 단계를 열었습니다.
  • 해당 버전을 받았다면 확장 삭제로 끝내지 말고, 키 확인 → 공식 스크립트로 제거 → 자격 증명 전부 교체 순서로 처리합니다.
  • 내 키가 “다른 회사의 다른 회사"까지 흘러갈 수 있다는 점, 그리고 AI 대화에 붙여 넣은 비밀값은 언젠가 기록으로 남는다는 점을 기억해 두면 좋겠습니다.
