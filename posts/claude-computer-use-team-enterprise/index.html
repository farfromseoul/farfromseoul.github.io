  • 대상은 Team·Enterprise, 상태는 베타이고 조직별로 순차 적용됩니다.
  • 조직 설정의 기본값은 꺼짐입니다. Owner·Primary Owner만 켤 수 있습니다.
  • 샌드박스가 없습니다. 연결한 폴더의 ‘읽기 전용’ 설정도 적용되지 않으니, 켜기 전에 앱 허용 목록과 역할 설정을 먼저 정해야 합니다.
  • 성능 수치(벤치마크)는 이번 발표에 없습니다(2026-11-22 확인 기준).

먼저 용어 몇 가지

  • 컴퓨터 사용(computer use): AI가 화면 캡처를 보고 클릭·입력을 흉내 내 사람처럼 앱을 쓰는 방식입니다. API나 커넥터가 없는 앱도 다룰 수 있지만 느리고 실수가 날 수 있습니다.
  • 커넥터(connector): Slack·Google Drive 같은 서비스에 API로 바로 붙는 연결 통로입니다. 화면 조작보다 빠르고 정확합니다.
  • 샌드박스(sandbox): 프로그램이 허락된 범위 밖을 건드리지 못하게 막는 격리 공간입니다.
  • MDM(Mobile Device Management): 회사가 직원 PC·노트북의 설정을 한꺼번에 관리하는 도구입니다(Jamf, Intune 등).
  • 번들 ID / AUMID: 각각 macOS 앱과 Windows 앱을 구분하는 고유 이름입니다. 앱 허용·차단 목록에 이 값을 씁니다.

개인 요금제와 비교하면, 개인 요금제는 2026년 3월 연구 미리보기로 시작해 지금은 Cowork·Claude Code에서도 쓸 수 있는 반면 Team·Enterprise 베타는 Claude Desktop의 통합 화면 중심으로 시작합니다.

관리자가 켜기 전에 정할 7가지

공식 설정 가이드(“Set up computer use for Team and Enterprise plans”)에 나온 내용을 체크리스트로 묶었습니다.

  1. 누가 쓸지 (역할): Enterprise는 컴퓨터 사용이 사용자 지정 역할(custom role)의 권한 항목입니다. 기본 역할(User·Admin·Owner)은 켜는 즉시 모두 쓸 수 있으니, 일부만 허용하려면 먼저 사용자 지정 역할을 만들어 두세요. 반영까지 약 15분 걸립니다. Team은 사용자 지정 역할이 없어 조직 전체에 똑같이 적용됩니다.
  2. 어떤 앱을 쓸지 (허용·차단 목록): ‘이 앱 차단’과 ‘이 앱만 허용’ 두 가지 목록이 있습니다. 앱 ID는 검증되지 않으니 오타가 없는지 직접 확인해야 하고, 변경은 사용자에게 닿기까지 약 1시간 걸립니다.
  3. 목록이 못 막는 것: Chrome 기반 브라우저 조작, 내장 브라우저, 웹사이트·확장 프로그램, 원격 데스크톱·가상 머신 안의 앱, 차단된 앱에서 복사한 텍스트, Windows 시작 메뉴·검색·파일 탐색기 등은 앱 목록으로 막히지 않습니다.
  4. 특정 PC에서 끄기 (MDM): Claude Desktop 5.1231.0 이상에서 computerUseEnabled 정책 값을 false로 배포하면 해당 기기에서 끌 수 있습니다. 이 값은 끄기만 가능하고 켜지는 못합니다. 또 ‘스킬 녹화’, Claude in Chrome, 로컬 MCP 서버 등은 이 값으로 막히지 않으니 완전한 잠금장치로 생각하면 안 됩니다.
  5. macOS 권한: 사용자는 ‘손쉬운 사용(Accessibility)‘과 ‘화면 및 시스템 오디오 녹화’ 권한을 줘야 합니다. 관리자 권한이 없는 직원은 IT 담당자의 도움이 필요할 수 있습니다. Windows는 별도 OS 권한이 필요 없습니다.
  6. 끌 때 걸리는 시간: 조직 설정을 꺼도 반영까지 약 1시간, 길게는 더 걸린다고 안내합니다. 사고가 났을 때 ‘즉시 차단’이 안 된다는 점을 사고 대응 절차에 넣어 두세요.
  7. 데이터: 화면 캡처가 대화와 함께 저장되고, 자동 안전 점검이 최근 캡처를 보며 Anthropic이 사본을 보관할 수 있습니다. 화면에 고객 정보·비밀번호가 떠 있으면 함께 찍힌다는 뜻입니다. 공식 도움말에는 컴퓨터 사용 전용 감사 로그 안내가 없습니다.

한계·주의할 점

  • 샌드박스 없음: Claude가 허용된 앱 안에서 하는 일은 사용자가 직접 하는 것과 같은 권한으로 실행됩니다. 메일 발송, 파일 삭제 같은 되돌리기 어려운 작업은 사람이 마지막에 확인하는 흐름을 유지하세요.
  • 느리고 실수할 수 있음: 화면을 보고 조작하는 방식이라 커넥터보다 느리고, 여러 단계 작업은 다시 시도해야 할 때가 있습니다. 커넥터가 있는 서비스는 커넥터를 먼저 쓰는 편이 낫습니다.
  • 화면에 뜬 지시문 주의: 웹페이지·문서 속에 AI를 속이려는 문구가 숨어 있을 수 있습니다(프롬프트 인젝션). 모르는 사이트나 외부에서 받은 파일을 연 상태에서 자동 작업을 맡기는 것은 피하세요.
  • 컴퓨터가 깨어 있어야 함: 웹·모바일에서 부르더라도 실제 작업은 Claude Desktop이 켜진 컴퓨터에서 일어납니다.
  • 문서 간 불일치: 개인 요금제용 도움말 일부에는 아직 “Team·Enterprise는 사용할 수 없다"는 오래된 문장이 남아 있습니다. 설정은 Team·Enterprise 전용 가이드를 기준으로 보세요.
  • 다른 회사 제품도 같은 문제: 화면을 직접 조작하는 AI 에이전트는 OpenAI·Google 등도 내놓고 있고, 샌드박스·권한 문제는 이 방식 전체의 공통 과제입니다. Claude만의 문제가 아닙니다.

나에게 맞는 선택

  • 취준생·대학생(개인 요금제 사용자): 이번 변경과 직접 관계는 없습니다. 다만 회사에 들어가면 이런 기능이 ‘관리자가 켜 주는 권한’으로 들어온다는 점, 그리고 화면 캡처가 저장된다는 점은 알아 두면 좋습니다.
  • 현업 직원(Team·Enterprise 사용자): 관리자가 켜기 전에는 메뉴가 보이지 않는 게 정상입니다. 켜진 뒤에도 앱마다 처음 한 번씩 승인을 물으니, 업무에 꼭 필요한 앱만 허용하세요.
  • IT·보안 담당자: 바로 전사로 켜기보다 사용자 지정 역할로 소수 파일럿 그룹 → 앱 허용 목록 → MDM으로 민감한 PC는 끄기 순서를 권합니다. 끄는 데 1시간 정도 걸린다는 점을 운영 문서에 적어 두세요.
  • 개발자: 터미널 Claude Code에서는 Team·Enterprise 컴퓨터 사용이 지원되지 않습니다. 반복 업무 자동화는 여전히 API·커넥터·스크립트가 더 안정적입니다.

정리

Claude의 컴퓨터 사용이 11월 20일부터 Team·Enterprise에 베타로 열렸습니다. 기능 자체보다 중요한 건 기본값 꺼짐, 샌드박스 없음, 앱 목록의 빈틈, 1시간의 반영 지연이라는 운영 조건입니다. 조직에서 쓸 계획이라면 역할과 앱 허용 목록부터 정하고, 소수 인원으로 먼저 써 본 뒤 넓히는 것이 안전합니다.
