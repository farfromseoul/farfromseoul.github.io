문제는 공개 직후 상황입니다. 보안 연구자들이 이 중 몇 개를 차례로 이으면 로그인 없이 서버에서 명령을 실행할 수 있다고 분석을 냈고, 보안 업체 watchTowr는 11월 25일 자사 허니팟(공격을 관찰하려고 일부러 열어 둔 미끼 서버)에서 실제 공격 시도를 봤다고 밝혔습니다.

이 글은 GeoServer를 직접 운영하는 분뿐 아니라, 회사·연구실·공공기관 프로젝트에서 “지도 서버가 어딘가 돌고 있는데 누가 관리하는지 모르는” 상황에 있는 개발자·인프라 담당자, 그리고 취약점 연쇄 공격을 공부하는 학생·취준생을 위한 정리입니다.

즉 고친 버전은 이미 한 달 전에 나와 있었고, 무엇을 고쳤는지가 공개되자마자 공격이 따라붙은 전형적인 흐름입니다. 업데이트를 미뤄 둔 서버가 가장 위험합니다.

핵심 개념 먼저

  • GeoServer: 지도 레이어·좌표 데이터를 표준 방식(OGC 표준)으로 웹에 제공하는 Java 기반 오픈소스 서버입니다. 공공 지도 서비스, 물류·부동산·환경 데이터 플랫폼에서 많이 씁니다.
  • WFS(Web Feature Service): 지도 위의 도형·속성 데이터를 요청해 받는 표준 인터페이스입니다. 보통 로그인 없이 열어 두는 경우가 많아 공격 입구가 되기 쉽습니다.
  • remember-me(로그인 유지) 쿠키: “로그인 상태 유지"를 누르면 브라우저에 남는 쿠키입니다. 서버는 비밀 키로 이 쿠키에 서명해 위조를 막는데, 그 키를 남이 알 수 있으면 아무나 로그인 쿠키를 만들 수 있습니다.
  • 역직렬화(deserialization): 저장·전송용으로 바꾼 데이터를 다시 프로그램 객체로 되살리는 과정입니다. 검증 없이 하면 공격자가 넣은 데이터가 코드처럼 실행될 수 있습니다.
  • RCE(Remote Code Execution, 원격 코드 실행): 공격자가 네트워크 너머에서 서버에 원하는 명령을 실행하는 것. 취약점 중 가장 심각한 결과입니다.

자세한 내용: 다섯 단계로 이어지는 연쇄

The Hacker News와 Ostorlab은 같은 다섯 CVE로 이어지는 연쇄를 설명합니다. 하나하나는 “정보가 조금 새는” 수준이어도, 이어 붙이면 로그인 없이 서버 장악까지 갑니다.

등급은 GeoServer 공식 보안 업데이트 기준입니다. 이 중 CVE-2026-129245는 두 매체 모두 GeoServer 측 CVSS v4.0 점수를 9.2로 전했습니다.

한계와 주의할 점

  • 어떤 CVE가 실제로 공격에 쓰였는지는 보도마다 표기가 다릅니다. watchTowr의 관찰을 전한 The Hacker News 기사 안에서도 CVE 번호가 한 곳에서 다르게 적혀 있고, Ostorlab은 “공격 시도"라고만 썼습니다. 어느 단계까지 성공한 공격인지도 공개되지 않았습니다.
  • 미국 CISA KEV(실제 악용이 확인된 취약점 목록) 등재 여부는 이 글을 쓰는 시점(2026-11-27)에 확인하지 못했습니다. 등재되면 공공기관 납품 시스템에는 조치 기한이 붙으니 따로 확인하세요.
  • 이 글은 공식 보안 공지의 본문 일부와 보도를 바탕으로 썼고, 개별 GitHub 보안 권고(GHSA) 원문은 직접 열어 보지 못했습니다. 세부 조건은 GeoServer 공식 권고를 기준으로 판단하세요.
  • 지난주 공개된 Java 자체의 Base64 취약점(Java4Shell)도 GeoServer 공식 블로그가 별도로 안내했습니다. GeoServer 업데이트와는 별개 문제라 둘 다 챙겨야 합니다. 자세한 내용은 Java4Shell 정리 글을 참고하세요.

독자가 할 일

GeoServer를 운영한다면

  1. 버전부터 확인합니다. 웹 관리 화면의 서버 정보(About/Status)에서 버전을 보고, 위 표의 버전보다 낮으면 바로 업데이트 계획을 잡습니다.
  2. 업데이트를 최우선으로 합니다. 고친 버전은 10월부터 나와 있었고, 지금은 공격 시도가 보고된 상태입니다.
  3. 바로 못 올린다면 노출을 줄입니다. (공식 안내가 아닌 일반적인 대응입니다) 관리 화면과 GeoServer 자체를 인터넷에 직접 열어 두지 말고, 꼭 필요한 서비스만 리버스 프록시 뒤에서 허용합니다.
  4. 업데이트 후에도 흔적을 봅니다. (일반적인 대응) 접근 로그에서 평소와 다른 서비스 경로 요청, 처음 보는 관리자 로그인, 새로 생긴 사용자·데이터 저장소 설정이 없는지 확인하고, 의심되면 관리자 비밀번호와 연결된 DB 비밀번호를 바꿉니다.

GeoServer를 직접 쓰지 않는다면

  • 팀이나 회사에 “지도 서버” 역할을 하는 무언가가 있는지 한 번 물어보세요. GIS 기능은 다른 제품 안에 GeoServer가 들어 있는 경우도 많습니다.
  • 공부하는 입장이라면, “작은 정보 노출 → 접근 규칙 우회 → 파일 읽기 → 인증 위조 → 코드 실행"으로 이어지는 이 연쇄는 Medium 등급도 무시하면 안 되는 이유를 보여 주는 좋은 사례입니다.

정리

  • GeoServer가 11월 23일 CVE 17개(Critical 1, High 12, Medium 4)를 공개했고, 수정은 10월 19일 배포된 3.0.2·2.28.6·2.27.7에 들어 있습니다.
  • 다섯 개를 이으면 로그인 없이 관리자 쿠키 위조 → 원격 코드 실행까지 갈 수 있다는 분석이 나왔고, 11월 25일 실제 공격 시도가 보고됐습니다.
  • 할 일은 단순합니다. 버전 확인 → 업데이트 → 못 하면 인터넷 노출 차단 → 흔적 점검.
