GitHub Copilot, 12월 14일 모델 6개 정리: 대체 모델은 대부분 자동으로 켜지지만 Fable 5.2는 관리자가 직접 켜야 합니다

2026년 11월 13일, GitHub가 Copilot에서 모델 6개를 12월 14일에 내린다고 공지했습니다. 결론부터 정리하면 이렇습니다.

  • 12월 14일부터 Claude Fable 5, Claude Haiku 4.5, Gemini 3.8 Flash, Gemini 4 Argon, Grok 4.6, Kimi K3를 Copilot 어디에서도 고를 수 없습니다.
  • 모델마다 대체 모델이 정해져 있고, Business·Enterprise 조직은 기본 설정이라면 대체 모델이 자동으로 켜집니다.
  • 예외가 있습니다. Claude Fable 5.2는 기본으로 꺼져 있어 관리자가 직접 켜야 하고, Kimi K3는 대체 모델이 아직 없습니다.
  • 연간 요금제를 쓰는 개인 구독자는 Haiku 4.5를 계속 쓸 수 있습니다.

이 글은 2026-11-16 확인 기준이며, 모든 내용은 GitHub 공식 공지(아래 출처 ①)에서 확인했습니다.

먼저 알아 둘 말

  • Copilot 모델 선택기(model picker): Copilot 채팅 창에서 어떤 AI 모델로 답을 받을지 고르는 목록입니다.
  • 지원 종료(deprecation): 해당 모델을 목록에서 빼고 더는 쓸 수 없게 하는 것입니다. 이번 공지는 “12월 14일에 빠진다"는 예고입니다.
  • 모델 정책(model policy): Business·Enterprise 관리자가 조직 구성원이 어떤 모델을 쓸 수 있는지 켜고 끄는 설정입니다.
  • 데이터 보관(data retention): AI 회사가 요청과 답변을 일정 기간 저장하는 것입니다. 반대로 저장하지 않는 계약을 **ZDR(zero data retention)**이라고 부릅니다.

영향 범위는 Copilot 채팅, 인라인 편집, ask·agent 모드, 코드 자동 완성까지 전부입니다. 즉 “채팅에서만 빠진다"가 아니라 이 모델을 고를 수 있던 모든 곳에서 빠집니다.

“자동으로 켜진다"는 말에는 조건이 붙습니다. 관리자가 전체 기본값(global default)을 꺼 두었거나 그 모델을 따로 꺼 두었다면 자동으로 켜지지 않습니다. 이 경우 Copilot 설정의 모델 정책에서 대체 모델을 직접 켜야 합니다.

주의할 점 1: Fable 5.2는 “자동 대체"가 아닙니다

Fable 5 → 5.2 교체가 가장 손이 많이 갑니다. GitHub의 Fable 5.2 추가 공지(11월 9일)에 따르면:

  • Fable 5.2는 Business·Enterprise에서 기본으로 꺼져 있고, 관리자가 Copilot 설정에서 Fable 5.2 정책을 켜야 합니다.
  • 이유는 데이터 보관입니다. Fable 5·5.1·5.2는 다른 Claude 모델과 달리 기본으로 데이터 보관이 필요합니다. Anthropic이 악용을 잡아내는 안전 분류기를 돌리려고 요청과 답변을 저장하며, 공지에 따르면 이 데이터는 모델 학습에는 쓰이지 않습니다.
  • 조건을 갖춘 기업은 올해 말까지 한시적으로 ZDR 예외를 받을 수 있지만, 승인을 받아도 모델이 자동으로 켜지지는 않습니다. 신청은 GitHub 지원팀이 아니라 계정 담당 팀을 통해서입니다.

그래서 회사 보안 정책상 “AI 업체가 데이터를 저장하면 안 된다"는 조직이라면, Fable 5를 쓰던 사람들을 Fable 5.2로 그냥 옮길 수 없을 수도 있습니다. 보안 담당자와 먼저 이야기해 보고, 안 된다면 다른 모델로 옮길 계획을 세워야 합니다.

주의할 점 2: 공지에 없는 것

공지만으로는 알 수 없는 부분도 있습니다.

  • 요금 차이: 새로 들어온 Fable 5.2와 Gemini 4 Carbon은 공지에 “제공사 정가로 사용량 기반 청구"라고만 나와 있고, 기존 모델과 비교한 비용 변화는 적혀 있지 않습니다. Copilot의 모델·가격 문서를 따로 확인해야 합니다.
  • 성능 차이: 대체 모델이 기존 모델과 같은 품질을 낸다는 보장은 공지에 없습니다. 특히 자동 완성처럼 빠른 응답이 중요한 곳에서는 직접 써 보고 판단하는 편이 안전합니다.
  • Kimi K3 사용자: 대체 모델이 아직 발표되지 않았습니다. Kimi K3는 오픈 웨이트(가중치가 공개된) 모델이라 원래 기본으로 꺼져 있는 모델이기도 해서, 직접 켜서 쓰던 조직이라면 다른 모델을 미리 정해 두는 게 좋습니다.
  • 제공 범위: Fable 5.2와 Gemini 4 Carbon은 Copilot Pro+, Max, Business, Enterprise 요금제에 들어 있습니다. 그 밖의 요금제에서 쓸 수 있는지는 공지에서 확인되지 않았습니다.

나에게 해당하는 일

개인 사용자(학생·취준생 포함)

  • 모델 선택기에서 빠지는 모델을 즐겨 쓰고 있었다면, 12월 14일 전에 대체 모델로 몇 번 써 보고 결과가 괜찮은지 확인해 두세요.
  • 연간 요금제로 Haiku 4.5를 쓰고 있다면 당장 바꿀 필요는 없습니다.

개발자

  • 저장소에 Copilot 프롬프트 파일이나 사용자 정의 에이전트 파일처럼 모델 이름을 적어 둔 설정이 있다면 찾아서 바꿔 둡니다. 예를 들어 .github 폴더 안에서 빠지는 모델 이름을 찾으려면 다음처럼 검색할 수 있습니다. (일반 grep 검색이며, fable 5는 Fable 5.2도 함께 찾으므로 결과를 눈으로 걸러야 합니다.)
grep -rniE "fable 5|haiku 4\.5|gemini 3\.8|gemini 4 argon|grok 4\.6|kimi k3" .github

조직 관리자

  1. Copilot 설정에서 전체 기본값(global default)이 켜져 있는지 확인합니다. 꺼져 있다면 대체 모델을 하나씩 켜야 합니다.
  2. Fable 5를 쓰던 팀이 있다면 Fable 5.2 정책을 켤지, 데이터 보관 조건을 받아들일 수 있는지 보안 담당자와 정합니다.
  3. Kimi K3를 쓰던 팀에는 임시로 쓸 다른 모델을 안내합니다.
  4. 12월 14일 뒤에 빠진 모델을 따로 지울 필요는 없습니다. GitHub가 알아서 목록에서 뺍니다.

정리

  • 12월 14일, Copilot에서 모델 6개가 빠지고 대부분은 같은 회사의 새 버전으로 자동 대체됩니다.
  • 손이 가는 곳은 두 군데입니다. Fable 5.2는 관리자가 직접 켜야 하고 데이터 보관 조건이 붙으며, Kimi K3는 대체 모델이 없습니다.
  • 요금과 성능 차이는 공지에 없으니, 자주 쓰는 작업으로 대체 모델을 미리 시험해 보는 것이 가장 확실합니다.
