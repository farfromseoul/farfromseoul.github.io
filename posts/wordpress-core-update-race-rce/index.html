워드프레스 '업데이트하는 몇 초'가 공격 통로였다 — CVE-2026-119977 정리와 업데이트 전에 막아 둘 경로

워드프레스 코어를 업데이트하는 몇 초 동안 로그인 없이 서버 코드를 실행할 수 있는 결함(CVE-2026-119977)이 실제 공격에 쓰여 CISA 목록에 올랐습니다. 원리와 영향받는 버전, 업데이트 전에 /wp-content/upgrade/를 막아야 하는 이유를 정리합니다.

보안 공지의 단골 조언은 “최신 버전으로 업데이트하세요"입니다. 그런데 이번에는 업데이트하는 그 순간이 공격 통로였습니다.

워드프레스(WordPress)는 10월 28일 보안 릴리스 7.1.4를 내면서 22개 취약점을 고쳤고, 그중 하나가 “코어 업데이트 중 경쟁 상태로 원격 코드 실행이 가능한” 결함 CVE-2026-119977입니다. 미국 사이버보안청(CISA)은 11월 3일 이 결함을 실제 악용이 확인된 취약점 목록(KEV) 에 올렸습니다.

이 글은 블로그·쇼핑몰·회사 홈페이지를 워드프레스로 운영하는 분, 그리고 PHP 서버를 관리하는 개발자를 위한 정리입니다.

이 글은 WordPress.org 릴리스 노트와 Patchstack·Cloud Security Alliance·The Hacker News 등 여러 보안 매체의 분석을 교차 확인해 정리했습니다. 한 곳에서만 나온 수치는 쓰지 않았습니다. (11월 12일 기준)

무슨 일이 있었나

날짜 (미국 기준)일어난 일
10월 28일WordPress 7.1.4 보안 릴리스. 22개 취약점(17개 공지) 수정, 4.7까지 이전 버전에도 같은 날 패치 배포
10월 28일보안 업체 Wordfence가 방화벽 규칙을 배포하고, 21시간 동안 업데이트 중 생기는 설치 파일 경로를 노린 요청 1만 8,500건 이상을 관측
10월 말일부 공격 출처가 같은 사이트들을 약 14.5시간 동안 반복 조회 — 업데이트가 시작되는 순간을 기다린 것으로 보임
11월 3일CISA가 KEV 목록에 추가, 미국 연방기관 조치 기한은 11월 6일

결함을 처음 보고한 사람은 보안 연구자 Umut Bayram입니다. 다만 공격이 실제로 성공한 사례는 아직 공개적으로 확인된 것이 없습니다. 지금까지 나온 것은 “시도"가 많다는 관측입니다.

먼저 용어 몇 가지

  • 경쟁 상태(race condition): 두 작업이 같은 자원을 거의 동시에 건드릴 때, 누가 먼저 도착하느냐에 따라 결과가 달라지는 버그입니다.
  • TOCTOU(Time-of-Check to Time-of-Use): “확인한 시점"과 “실제로 쓰는 시점” 사이 틈에 상태가 바뀌어 생기는 경쟁 상태의 한 종류입니다.
  • RCE(Remote Code Execution, 원격 코드 실행): 공격자가 원격에서 서버에 자기 코드를 실행시킬 수 있는 상태입니다. 사실상 서버를 넘겨주는 것과 같습니다.
  • CISA KEV(Known Exploited Vulnerabilities): 미국 CISA가 “실제 공격에 쓰이는 것이 확인됐다"고 판단한 취약점 목록입니다. 패치 우선순위를 정할 때 가장 많이 참고하는 기준 중 하나입니다.
  • CVSS: 취약점의 심각도를 0~10점으로 매기는 국제 기준입니다. 이번 건은 8.1점(높음)입니다.

자세한 내용: 업데이트 중 몇 초 동안 무슨 일이 벌어지나

1. 업데이트는 “새 워드프레스 한 벌"을 잠시 펼쳐 놓는다

워드프레스가 코어를 업데이트할 때는 새 버전 압축 파일을 내려받아 wp-content/upgrade/ 아래 작업 폴더에 통째로 풀어 놓은 뒤, 필요한 파일을 실제 사이트로 복사하고 작업 폴더를 지웁니다. 문제는 이 폴더가 웹에서 접근 가능한 위치에 있다는 점입니다.

여러 분석을 종합하면 7.1.4 이전에는 다음 세 가지가 겹쳤습니다.

문제왜 위험했나
작업 폴더 이름을 예측할 수 있었음공격자가 경로를 미리 알고 그 주소를 계속 두드릴 수 있음
정리 과정에서 디렉터리 목록을 막는 index.php가 지워졌음서버 설정에 따라 폴더 목록이 보여 경로가 드러날 수 있음
풀어 놓은 파일에 설치 마법사(wp-admin/setup-config.php)가 포함이 파일은 기존 사이트 설정을 찾지 못해 “새로 설치” 화면을 띄움

2. 공격자는 “새로 설치” 화면을 가로챈다

공격자가 업데이트 몇 초 사이에 작업 폴더의 설치 마법사에 먼저 도착하면, 이 마법사를 자기가 준비한 데이터베이스에 연결할 수 있습니다. 그다음에는 관리자 계정을 만들고 플러그인을 올리는 식으로 PHP 코드를 실행할 수 있다는 것이 분석의 요지입니다.

또 하나 눈여겨볼 점은 워드프레스 안에서 도는 보안 플러그인(PHP 방화벽)으로는 막을 수 없다는 것입니다. 작업 폴더에 풀린 사본은 내 사이트의 플러그인과 상관없이 자기 파일만으로 실행되기 때문입니다.

3. 영향받는 버전과 고쳐진 버전

브랜치고쳐진 버전

6.8 / 6.76.8.12 / 6.7.11

4.6 이하패치 없음 — 더 이상 보안 업데이트를 받지 않음

7.1.4에서는 작업 폴더 이름에 무작위 16글자를 붙이고, index.php를 지우지 않고 유지하며, 작업 폴더의 wp-config.php가 실제 사이트로 복사되지 않게 바꿨습니다.

4. 심각도 평가가 엇갈린다

평가 주체판단
Wordfence (CVE 발급 기관)CVSS 8.1, 높음 — 로그인·사용자 동작 없이 가능, 다만 공격 난이도(AC)는 높음

창이 몇 초뿐이라 “어렵다"는 평가와, 업데이트할 때마다(자동 업데이트 포함) 창이 다시 열린다는 점 때문에 “무시하면 안 된다"는 평가가 함께 나옵니다. 여러 분석가는 등급보다 KEV 등재 여부와 내 사이트의 노출 정도로 우선순위를 정하라고 권합니다.

한계와 주의할 점

  • “업데이트하면 끝"이 아닙니다. 아이러니하게도 7.1.4로 올리는 그 업데이트 자체가 아직 고쳐지지 않은 옛 업데이트 코드로 실행됩니다. 그래서 여러 보안 업체가 업데이트 전에 작업 폴더 경로부터 막으라고 권합니다.
  • 성공 사례는 아직 확인되지 않았습니다. 관측된 숫자는 대부분 방화벽이 막은 “시도"입니다. 그렇다고 안심할 근거도 되지 않습니다.
  • 업체마다 집계 방식이 다릅니다. Wordfence 수치는 기간과 집계 기준이 서로 달라 단순히 더하거나 비교하면 안 됩니다.
  • 4.6 이하 사이트는 고칠 방법이 없습니다. 오래 방치된 캠페인 페이지나 사내 홈페이지가 여기에 속하기 쉽습니다.

독자가 할 일

워드프레스 사이트를 운영한다면

  1. 업데이트 전에 /wp-content/upgrade/ 경로를 웹 서버에서 막으세요. 웹 서버 설정에서 이 경로 접근을 거부하고, 브라우저로 열었을 때 403(접근 거부)이 나오는지 확인합니다. Nginx라면 공식 접근 제어 지시어(deny)로 이렇게 막을 수 있습니다.

    location ^~ /wp-content/upgrade/ {
    deny all;
}

    Apache는 가상 호스트의 <Directory> 블록에 Require all denied를 쓰는 방식이 권장됩니다. 공유 호스팅처럼 웹 서버 설정을 못 바꾸는 환경이라면 호스팅 업체에 이 조치를 했는지 문의하세요.

  2. 그다음 자기 브랜치의 고쳐진 버전으로 올리세요. 관리자 화면의 알림판 → 업데이트에서 하거나, WP-CLI를 쓴다면 먼저 버전을 확인합니다.

    wp core version

  3. 업데이트 후 코어 파일이 원본과 같은지 확인하세요.

    wp core verify-checksums

  4. 10월 말 이후 업데이트를 했다면(자동 업데이트 포함) 흔적을 점검하세요.

    • 모르는 관리자 계정이나 설치한 적 없는 플러그인이 있는지
    • wp-config.php의 데이터베이스 주소·계정이 바뀌지 않았는지
    • wp-content/upgrade/ 아래에 남은 PHP 파일이 있는지 (평소에는 index.php만 있어야 정상)
    • 웹 서버 로그에서 업데이트 시각 전후로 wp-content/upgrade/.../setup-config.php 요청, 특히 200 응답이 있는지

  5. 4.6 이하 사이트가 있다면 목록부터 만드세요. 지원 버전으로 옮기거나 인터넷에서 분리하는 것 말고는 방법이 없습니다.

정리

  • CVE-2026-119977은 워드프레스가 코어를 업데이트하는 몇 초 동안 웹에서 접근 가능한 작업 폴더에 설치 마법사가 노출되는 결함입니다.
  • 로그인 없이 원격 코드 실행까지 이어질 수 있고, 실제 공격 시도가 관측돼 CISA KEV에 등재됐습니다.
  • 7.1.4와 4.7까지의 각 브랜치 보안 릴리스에서 고쳐졌고, 4.6 이하는 패치가 없습니다.
  • 순서가 중요합니다. /wp-content/upgrade/를 먼저 막고 → 업데이트하고 → 흔적을 점검하세요.
  • “업데이트 절차 자체도 공격면이 될 수 있다"는 점은 워드프레스뿐 아니라 자동 업데이트를 하는 모든 서비스에 해당합니다.
